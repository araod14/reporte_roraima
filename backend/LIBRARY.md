# Biblioteca Automatización Roraima

La biblioteca usa los 320 PDF de `info_tps/` (375 MB), PostgreSQL 16 existente y un modelo multilingüe ONNX local de 384 dimensiones. Los PDF, el texto y el índice permanecen en el VPS. El servidor envía a Gemini únicamente la pregunta, hasta ocho mensajes recientes y unos 26 000 caracteres de fragmentos recuperados (aproximadamente 4 000–8 000 tokens documentales). No habilita herramientas, búsqueda web ni archivos aportados por usuarios.

## Acceso y proveedor

Todas las cuentas existentes de `users` pueden abrir la biblioteca; cada conversación se filtra por `user_id`. Los PDF y las imágenes de sus páginas se sirven desde endpoints autenticados y se abren como Blob en el navegador. El visor usa la imagen de la página citada en teléfono y ofrece un botón para el PDF completo. No hay enlace público a `info_tps/`.

La generación usa **`gemini-3.5-flash-lite`** mediante `streamGenerateContent`, con razonamiento `low` y registro del uso real cuando Gemini lo devuelve. La clave nueva está guardada con permisos `0600`; el propietario confirmó que revocó la clave expuesta y que el proyecto es **Free Tier sin facturación vinculada**. No se usan la suscripción ChatGPT Pro ni claves de Qwen.

### Pasos del propietario para usar solo el nivel gratuito

1. Abrir [Google AI Studio](https://aistudio.google.com/apikey) con una cuenta de Google. Crear o seleccionar un proyecto que AI Studio muestre como **Free Tier** y crear una clave API para ese proyecto. **No pulsar “Set up billing” ni vincular una cuenta de Cloud Billing.** Algunos proyectos o cuentas no son elegibles para Free Tier; en ese caso, la biblioteca debe permanecer cerrada. [Facturación](https://ai.google.dev/gemini-api/docs/billing), [elegibilidad](https://ai.google.dev/gemini-api/docs/troubleshooting).
2. Comprobar en AI Studio los [límites vigentes del proyecto](https://ai.google.dev/gemini-api/docs/rate-limits) para `gemini-3.5-flash-lite`. El nivel gratuito ofrece tokens de entrada y salida gratis sujetos a límites por proyecto; al agotarlos devuelve un error y la biblioteca no cambia a otro proveedor ni a una clave pagada. La aplicación no usa archivos, búsqueda ni otras herramientas del proveedor.
3. Guardar la clave solo en el VPS como `library_secrets/gemini.key`, una línea, con permisos `0600`; el directorio `library_secrets/` debe tener `0700`. No pegarla en chat ni subirla a Git. [Guía oficial de claves](https://ai.google.dev/gemini-api/docs/api-key).
4. En `deploy/.env` (fuera de Git), establecer `LIBRARY_GEMINI_FREE_TIER_CONFIRMED=true` **únicamente después** de comprobar que esa clave pertenece a un proyecto Free Tier sin facturación vinculada. Esta variable impide llamadas accidentales antes de completar el paso, pero no puede comprobar la facturación de Google por sí sola. No vincular facturación a ese proyecto mientras se use esta integración.
5. Antes de publicar, ejecutar `python -m app.scripts.check_gemini` dentro de la imagen backend con la clave y la variable configuradas. Imprime una respuesta mínima y `usage`, sin mostrar la clave. Después de desplegar con autorización, comprobar `GET /api/library/status` autenticado y realizar una consulta breve sobre un manual. El estado `ready: true` confirma la configuración local, **no** que el proveedor haya respondido; la primera respuesta completada confirma la conexión.

**Tratamiento de datos:** el usuario aceptó probar el nivel gratuito tras conocer su condición. [Google indica](https://ai.google.dev/gemini-api/terms) que puede usar las entradas y respuestas del nivel gratuito para mejorar productos y que revisores humanos pueden verlas; pide no enviar información confidencial. La biblioteca limita el envío a fragmentos recuperados, pero esos fragmentos proceden de manuales privados. No cargar PDF completos ni datos personales en el prompt. Si la colección no puede someterse a estas condiciones, mantener la generación desactivada.

## Ingesta y despliegue

El trabajador también importa `info_tps/Inventario de materiales.xls` cada hora. La hoja `Hoja1` aporta descripción, número de parte, SAP Pz (número POZ), SAP PDVSA, cantidad, ubicación y estante; la hoja `Movimiento` no se interpreta como existencia actual. Si el hash no cambia, no reimporta. Si el XLS nuevo es inválido, conserva el último inventario válido y muestra el error en `/api/library/status`. Las respuestas citan hoja y fila, y una cantidad cero significa «sin existencia». Los fragmentos de filas pertinentes se envían a Gemini bajo las mismas condiciones descritas arriba para los manuales.

1. Crear copia lógica de PostgreSQL y copias de `deploy_reports` e `info_tps/` antes de migrar. El respaldo inmediato de la publicación está en `backups/library-deploy-20261027-215325/`: `database.dump`, `reports.tar`, `manuals.tar`, `frontend-dist.tar`, `deploy.env`, `library-index.dump` y `SHA256SUMS`. Su directorio es privado (`0700`), los archivos sensibles son `0600` y se verificaron con `sha256sum -c SHA256SUMS`. El respaldo previo `backups/library-predeploy-20261027/` se restauró en una base temporal para probar migración y reversión. Conservar también `library_secrets/` cifrado fuera del repositorio; su contenido no está en esos respaldos.
2. Validar el frontend con `cd app && npm run build:check` y revisar `alembic upgrade head` contra una copia de la base. **`app/dist` está montado directamente en Caddy de producción:** ejecutar `npm run build` allí cambia los archivos públicos al instante. La migración `20261020_library` solo crea tablas e índices nuevos.
3. Tras autorización de publicación, compilar el frontend en un directorio temporal y copiar los archivos al `app/dist` montado por Caddy, dejando `index.html` y `sw.js` para el final. La publicación de 2026-10-27 importó el índice aislado ya validado en una transacción: los SHA-256 de los 320 PDF coincidían. `library_worker` recorre los PDF cada hora; los 320 se marcaron `unchanged` en su primera pasada de producción. Si se añade o modifica un manual, el hash SHA-256 hace que solo ese archivo se reprocese. Supervisar sus logs y `library_documents.ocr_pages`.
4. El modelo ONNX se descarga una vez al volumen `library_models`. El trabajador lo usa en CPU. Para repetir manualmente: `python -m app.scripts.ingest_library` dentro de la imagen backend, con `DATABASE_URL`, `LIBRARY_PDF_DIR` y `HF_HOME` configurados.

Los PDF con menos de 80 caracteres extraíbles por página pasan por OCR español/inglés. Las tablas y procedimientos se mantienen como líneas dentro de cada fragmento; cada fragmento conserva sección, idioma y página PDF. Los documentos modificados se reemplazan de forma transaccional. Los archivos eliminados del directorio permanecen en el catálogo hasta que se retiren explícitamente; no se borran automáticamente para evitar pérdida accidental.

## Reversión

Para desactivar solo Gemini, establecer `LIBRARY_GEMINI_FREE_TIER_CONFIRMED=false` y recrear la API. Para revertir la publicación, detener `library_worker`, copiar `backups/library-deploy-20261027-215325/frontend-dist/` sobre `app/dist/`, volver a etiquetar `rollback/deploy/api:pre-library-20261027-215325` como `deploy-api:latest` y recrear solo la API sin reconstruir la imagen. Las tablas nuevas pueden permanecer vacías o conservar el índice para una reparación posterior. Ejecutar `alembic downgrade 20260912_diarios` con la imagen nueva **solo si se quiere retirar la biblioteca y tras confirmar el respaldo**: elimina el historial y el índice. Los reportes y sus hashes no se modifican. El Compose de desarrollo usa el proyecto `roraima-library-dev` para aislar sus contenedores y volúmenes de producción.

## Validación previa a la publicación

El 27 de octubre de 2026, `gemini-3.8-flash` devolvió HTTP 503 y otra llamada agotó el tiempo de espera. `gemini-3.5-flash-lite` respondió HTTP 200 tanto en generación simple como progresiva (`OK`, 7 tokens totales), por lo que se eligió ese modelo gratuito. La colección completa se indexó en la base de desarrollo aislada: **320 documentos, 56 146 fragmentos, 1 646 páginas con OCR**, cero documentos sin fragmentos y cero páginas fuera del PDF. Una segunda pasada marcó los 320 archivos como `unchanged`, sin duplicados. La búsqueda de UCN en español recuperó manuales en inglés; las consultas cálidas de código y versión tardaron unos 4 segundos en la prueba local.

Se probaron código exacto `AMCL06`, comparación R510/R520, seguimiento UCN/NIM, pregunta ajena, pregunta mixta, inyección de instrucciones y código inexistente. La comparación citó páginas 235 de `sw09650`, 25 de `sw11570` y 190 de `sw11601`; el texto de esas páginas se contrastó localmente. La respuesta final conserva solo párrafos con referencias válidas. El consumo real observado fue de 6 260 a 9 593 tokens totales por consulta de prueba, según `usageMetadata`; la primera prueba mínima usó 7 tokens. Esto mide ejemplos, no garantiza la calidad de todas las respuestas.

Las pruebas de API cubrieron aislamiento de conversaciones entre dos usuarios, búsqueda de historial, renombrado, eliminación, regeneración, identificadores repetidos, PDF y página protegidos, y error 404 para una página fuera de rango. En Chromium se comprobó escritorio, teléfono, detención sin respuesta parcial guardada y apertura de la página 379 de `am27610` como imagen visible en móvil; las capturas están en el respaldo privado. La migración se aplicó y revirtió sobre una restauración temporal de producción: mantuvo 7 usuarios y 22 reportes. La base temporal se retiró después de esa prueba. El JWT expuesto se rotó antes de esta publicación.

## Publicación de producción — 2026-10-27

El propietario autorizó la publicación. Se verificó el respaldo inmediato, se aplicó `20261020_library`, se importaron **320 documentos y 56 146 fragmentos** desde la base aislada y se verificaron de nuevo los SHA-256 de los PDF montados en producción. El trabajador marcó los 320 como `unchanged`. Caddy sirve el nuevo frontend y el dominio HTTPS responde `200`; `/api/library/status` sin sesión responde `401`. Una consulta interna temporal sobre `AMCL06` respondió progresivamente con 8 fuentes, abrió la página protegida y reportó **8 072 tokens**; la conversación se eliminó. La API quedó saludable y `LIBRARY_GEMINI_FREE_TIER_CONFIRMED=true`. Los contenedores de desarrollo siguen detenidos, conservando su volumen con el índice.
